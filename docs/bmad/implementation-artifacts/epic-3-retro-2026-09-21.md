### Aggregate views

**AV-1 · Architecture delta: clean at the import level.** dependency-cruiser ran at both ends of the range: `f7359b4` cruised 263 modules and `acfb757` 276, with 0 violations at each. No module imports another at the end. The new edges all run into `src/shared` (`status-page` → `shared/{cqrs,db,domain,exceptions,testing}`, `maintenance` → `shared/domain`), and the one into `server/build-app.ts` comes from `status-page`'s integration tests, as every module's do. *Instance:* accept.

**AV-2 · The coupling dependency-cruiser cannot see grew again.** `public-status.repository.ts` names seven tables owned by three other modules: `services` and `service_groups` (service), `incidents`, `incident_service_impacts` and `incident_updates` (incident), `maintenance` and `maintenance_services` (maintenance). Epic 2's AV-2 prevention, a structural test allowlisting the tables each module may name, is still deferred. *Instance:* accept as documented. *Prevention:* defer, but set the trigger: the next story that adds a foreign-table read adds the allowlist test first.

Export the active subset from `status-inputs.ts` and use it in both. *Prevention:* the file's header names ladder subsets as well as ladders.

#### Correctness and security

**R-1 · Private and archived services leak through affected-service ids (ADV-1, EC-1, EC claim 3, VGL-7, AV-7).** `listActiveIncidents` reads `incident_service_impacts` and `listOpenMaintenance` reads `maintenance_services` (`public-status.repository.ts:151–157`, `:219–225`) with no join to `services`. Reproduced on the running API: a private service's id appears on two incidents and a window, and an archived service's id on the window. The ids are opaque, but they announce components the organization chose not to publish. A renderer given an id that names nothing in `groups` has nothing to draw, which breaks the wireframe's "Affects:" line. No fixture ever attached a hidden service to an incident or window, and the E2E exclusion checks look for names, not ids. *Instance:* fix now. Join `services` and keep only `is_public` and unarchived rows, then test with the hidden and archived fixtures attached to both. *Prevention:* an exclusion criterion is tested at every place the excluded thing can be *referenced*, not only where it is listed.

**R-2 · An incident or window that touches only non-public services is published whole (EC-2, ADV-1).** Reproduced: "Internal ledger rebuild", which affects only a private service, is listed with its title and timeline, and so is a window touching only private and archived services. DOMAIN is silent: `is_public` is defined on services only (`DOMAIN.md:57`). An incident naming *no* service is a different case, and 3.3's fixtures rely on it being shown, since blast radius is often unknown at first. *Instance:* a human decision; see Open questions.

**R-3 · "One transaction, a single answer" is false (ADV-3, EC-3, EC claim 1, VGL-8).** The handler says its three reads share a transaction so that "the page is a single answer" (`get-public-status-page.handler.ts:45–47`), and 3.3's commit repeats it. `withTenantTransaction` is `sql.begin` with no isolation level (`tenant-transaction.ts:83`), so this is READ COMMITTED, where each statement takes its own snapshot. On top of that, `last_known_status` is written by an asynchronous recompute after the incident commits, so no snapshot makes services agree with incidents. The sabotage the commit cites, reading outside the transaction, proved tenant scoping, not consistency. **This is Epic 2's lesson P5, "same transaction is not serialized", repeated by the same author one epic later.** *Instance:* fix now. Read the page under `repeatable read read only`, through an isolation option on `withTenantTransaction`, and rewrite the comment to state the recompute lag honestly. *Prevention:* lesson P3.

**R-4 · Draft-era notes would publish when a draft is confirmed (ADV-2, EC-4).** `post-incident-update` has no status guard and records the incident's current status (`post-incident-update.handler.ts:42–48`), so an update posted to a draft is stored with status `draft`. The public timeline read selects every entry of an active incident (`public-status.repository.ts:159–172`), so confirming the draft publishes those entries. They include operators' triage notes, and from Epic 5 monitor-generated text. Nothing creates drafts through the API until Epic 5, but a draft plus a posted update reaches it today. *Instance:* fix now, since the filter is one predicate (`status <> 'draft'`) plus a test. It also informs Epic 2's D-4.

**R-5 · The first anonymous database-backed surface has no bound on cost (ADV-4, EC-5, EC-6).** There is:
- no rate limit (no plugin in `package.json`);
- no cap on GraphQL aliases, because mercurius is registered with neither `validationRules` nor a complexity limit (`src/server/index.ts:15–19`). The adversarial lens measured one 6.2 KB anonymous request aliasing `publicStatusPage` 100 times, which ran 100 full page compositions against a pool of 10 connections;
- no `Cache-Control` or `ETag` (Behavior verification), and `generatedAt` changes on every response, so a poller cannot tell "unchanged";
- no bound on payload size: every update of every active incident, and every future window.

The alias measurement was the lens's, and was not repeated here. The absence of any limit was re-checked in the code. *Instance:* a human decision on what lands before Epic 4, which adds long-lived anonymous SSE connections; see Open questions.

**R-6 · GraphQL hands internal error text to anonymous callers (ADV-5, EC-10).** mercurius has no `errorFormatter` (`src/server/index.ts:15–19`), so a resolver's error message reaches the client unmasked, while REST masks everything that is not an `ExceptionBase`. The lens reproduced a Postgres encoding error returned verbatim in a 200 response. A connection failure would name the database host the same way. *Instance:* fix now. Add an `errorFormatter` that passes `ExceptionBase` messages through, replaces the rest with the masked message plus the correlation id, and logs the original.

**R-7 · Anonymous error-log amplification** is AV-9 above (EC-11, ADV-4). It is listed here because both lenses reached it independently.

**R-8 · The slug's input domain is unconstrained (ADV-6, EC-8, EC-9).**
- A NUL byte (`/status/%00`) reaches Postgres and returns a 500 (22021, logged at error level). Measured by the lens; the parameter is passed unchecked.
- A slug longer than Fastify's default `maxParamLength` of 100 gets the *router's* 404, which echoes the path, instead of the handler's uniform one. That breaks 3.2's "one answer for every miss", and GraphQL would still serve such a page.
- Better Auth accepts any non-empty slug, so an organization can own a slug no URL reaches.
- A slug released by a rename can be registered by another organization, whose page then answers the old links and pollers (EC-9).

*Instance:* fix the route and resolver now: a slug pattern and maximum length, with anything outside them getting the handler's 404. The Better Auth creation rule and slug history need a decision; see Open questions.

**R-9 · The parity contract compares nothing for this capability (ADV-7).** The spec reads each slice's `.schema.ts` as the REST request shape (`api-surface-parity.spec.ts:66`). This slice's `.schema.ts` re-exports the *response* DTO, under a comment claiming "as every other route does", which is false. Because `publicStatusPage(orgSlug: ID!)` takes a scalar, `sdlPayloadFields` returns `undefined` and the spec `continue`s (`:193`). Story 3.3's criterion "held by the parity contract for the request shape" is therefore unmet. It passed only because the guard skipped it, and one drift is already observable: REST's `minLength: 1` against GraphQL's `ID!`, which accepts `""`. *Instance:* fix now. Put the request params schema in `.schema.ts`, import the response schema from `dtos/`, and make the spec fail rather than skip when both files exist and nothing was compared.

**R-10 · The public contract is built from admin types (ADV-8).** `PublicStatusIncident.updates` is `[IncidentUpdate!]!`, the incident module's admin type. The status enums come from command slices' SDL. A field later added to `IncidentUpdate` for operators, such as an author, becomes selectable anonymously through `publicStatusPage`. That is the coupling the TypeScript ladders were moved to `shared/domain` to avoid, now in SDL, where no guard looks. *Instance:* fix now. Declare the public update type in the status-page SDL, and move the shared enums beside `status-inputs.ts`.

**R-11 · "Cannot be used to enumerate organizations" cannot hold (ADV-9).** Story 3.2's criterion (`epics.md:981`) says the uniform 404 prevents enumeration. But a hit answers 200 with the organization's name, and every organization has a public page from the moment it is created: there is no publish setting, and `is_public` defaults to true. The 404 does reveal nothing beyond "not found"; the claim overreaches. *Instance:* a human decision on an opt-in publish setting; see Open questions. Either way, reword the criterion.

**R-12 · The banner can read `operational` beside a live critical incident (ADV-10).** `overallStatus` reduces only the public services' statuses (`public-status-page.present.ts:24–26`). An active incident naming no service, or only private ones, is listed under a banner that ignores it. Observed: `degraded` beside a listed `major` incident. The rule exists only in the wireframe; DOMAIN defines no page-level status. *Instance:* decided together with R-2; see Open questions.

**R-13 · Tied rows have no stable order (ADV-13, EC-7).** The services query ends at `s.name`, and names are not unique, so equal rows can swap between requests. Two groups tied on display order and name can interleave, which lets the presenter flip their order. The incident and window queries end with `id`; this one does not. *Instance:* fix now by adding `g.id` and `s.id` as final tiebreakers.

**R-14 · On the anonymous surface, one misconfiguration exposes every tenant (ADV-14).** No repository in the codebase has an explicit `org_id` predicate: 0 of 7 `*.repository.ts` files. RLS is the only tenant boundary, although README calls it "defense in depth" (`README.md:55`). The check that the runtime role is neither superuser nor `BYPASSRLS` exists only in an integration test. In Compose, the owner role is the superuser, and its URL sits one line from `DATABASE_URL` in `.env.example`. Point `DATABASE_URL` at it, and `/status/:slug` returns every tenant's incidents to anyone. *Instance:* fix now at boot: `api` and `worker` refuse to start when `current_user` has `rolsuper` or `rolbypassrls`. *Spec:* reconcile README's wording with the as-built, or decide to add predicates; see Open questions.

**R-15 · Browsers on another origin cannot read the page (ADV-15).** CORS is registered with `origin: false` (`src/server/index.ts:33`), and Helmet's defaults apply. The epic records no decision on browser consumption, and Epic 4's SSE route inherits whatever it decides. *Instance:* a human decision; see Open questions.

**R-16 · The public allowlist exempts whole files (ADV-16).** `PUBLIC_BY_DESIGN` is keyed by file path, and the check is a substring search for `resolveOrganizationContext(` (`authenticated-surface.spec.ts:26–37`, `:64–65`). A mutation added to the public resolver file later would be exempt without review. That is Epic 2's R-1 shape again. *Instance:* fix before Epic 4 adds the second public route. Allowlist per operation: `GET /status/:orgSlug` and `Query.publicStatusPage`.

**R-17 · The uptime day is missing the field that colors a bar (ADV-17).** DOMAIN's `uptime_rollups` carries a per-day `worst_status` (`DOMAIN.md:323`). The payload's day object has only `date` and `uptimeRatio`, and nothing says whether a day with no checks is omitted or zero. The contract was declared final so that Epic 5 would not have to break it. *Instance:* fix now, while `services` is `[]` and no integrator depends on it. Add a nullable `worstStatus`, and document how missing days are represented.
